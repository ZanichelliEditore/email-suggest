# Dev-dependency stack: TypeScript, vitest and Biome on `node:24-alpine`

- **Status:** Active
- **Date:** 2026-09-28
- **Author:** email-suggest team
- [x] Implemented

## Context

Phase 1 builds a TypeScript library, and SPEC §6 fixes its shape: zero
runtime dependencies, `strict` TypeScript, `tsc` emitting ES2020 ES modules
plus `.d.ts` files, no bundler. Building it needs a compiler, a test runner
and a linter/formatter. None may land without an RFC: AGENTS.md rule 3 puts
every new dependency through one, and SPEC §12 requires this stack to be
accepted before Phase 1's first code.

Constraints:

- **Docker is the only local path** (SPEC §7). Node is not installed on the
  host, so every tool runs inside a Node Alpine container, and Alpine
  uses musl, not glibc. Any tool that ships a native binary must ship a musl
  build.
- **Reproducible.** Two contributors, or a contributor and CI, must get the
  same tool versions from the same commit.
- **Small and fresh.** Each package installed is supply-chain surface, and
  pins must not rot: Dependabot already keeps the GitHub Actions pins fresh
  (`.github/dependabot.yml`).

## Decision

**1. Three direct dev dependencies, pinned to exact versions** (latest
stable on 2026-09-28):

| Package | Version | Role |
|---|---|---|
| `typescript` | `7.0.2` | `tsc`: type-check and emit `.js` + `.d.ts` |
| `vitest` | `5.0.2` | test runner for `test/*.test.ts` |
| `@biomejs/biome` | `2.5.14` | lint and format, one tool |

vitest declares `vite` as a peer dependency, and npm installs it
automatically (`vite` 8.3.1, which brings `rolldown` 1.2.11). It stays out
of `package.json`; the lockfile pins it.

**2. Pinning and install.**

- `package.json` lists exact versions, with no `^` or `~`.
- `.npmrc` sets `save-exact=true`, so a later `npm install <pkg>` keeps that
  rule, and `ignore-scripts=true`, so no package runs an install script.
- `package-lock.json` is committed, and the container installs only with
  `npm ci`, which fails when the lockfile and `package.json` disagree.

**3. Base image pinned by tag and digest:**

```dockerfile
FROM node:24-alpine@sha256:ebfe2f90462722a7a4de65e91990e97fe0d401c70e0e762c5b53302f905ec1c1
```

On 2026-09-28 that digest is Node 24.21.0 with npm 11.19.0. It is the
multi-arch index (linux/amd64, linux/arm64 and linux/s390x), not one platform's
manifest, so each host pulls its own architecture. The tag records intent
for readers and for Dependabot; the digest makes every build use the same
image.

**4. Dependabot keeps the pins fresh, but never bumps a major.** T-002 adds
a `docker` entry and T-003 an `npm` entry to `.github/dependabot.yml`,
weekly like the existing `github-actions` entry. Both entries ignore
`version-update:semver-major`: a new Node line, or a new major of
TypeScript, vitest or Biome, is a deliberate change that amends this RFC,
not a line in a routine weekly PR. Minor and patch updates, and digest
refreshes, are grouped into one PR per ecosystem.

**Why this wins.** It covers the three jobs with three packages and no
workaround on Alpine (spike below). Biome replaces two tools, a linter and
a formatter, with one binary. npm ships in the image, so no package manager
is added. Over `node:test`, the one test-runner option with fewer packages, vitest wins
on module resolution; see Alternatives.

**Spike, 2026-09-28**, in disposable containers outside the repo, run at
the digest above and at the `node:22-alpine` digest
`sha256:0a7108bf6c7bf5de370ffb1a3ed6be93d405b43ff159f681a8d18c0e2bc2e402` (Node 22.23.3), with the
same results on both:

- `npm install` of the three packages: 39 packages in the tree, 130 MB
  `node_modules`, `npm audit` reports 0 vulnerabilities.
- `tsc` with `strict`, `target: ES2020`, `module: NodeNext` and
  `declaration: true` emitted `a.js` and `a.d.ts`.
- `biome check` ran and reported format and import-order findings.
- `vitest run` passed a test importing a `.ts` source.
- `npm ci --ignore-scripts` installed from the lockfile, and all three
  tools still ran.
- The native binaries resolved on x86_64 were
  `@typescript/typescript-linux-x64` (a Go binary with no libc
  requirement), `@biomejs/cli-linux-x64-musl` and
  `@rolldown/binding-linux-x64-musl`. All three projects also publish
  linux-arm64 builds (musl for Biome and rolldown), but arm64 was not run:
  this host has no arm64 emulation.

## Consequences

**Easier.** One toolchain per commit, identical for every contributor.
Nothing needs installing on the host but Docker. The published package
stays at zero runtime dependencies: all of this is dev-only.

**Costs and what gets harder.**

- **Docker must be running** for every `make quality` and for every commit
  that runs the pre-commit Biome hook (SPEC §7). Each hook run starts a
  container. With Docker stopped, those commits fail until it is started.
- **Every native tool needs a musl build.** All of today's have one. A
  future tool without one would break the image. The fallback is
  `node:24-slim` (Debian, glibc): a one-line `FROM` change plus rebuilding
  the `node_modules` volume.
- **Install scripts are blocked, silently.** The only package in today's
  lockfile that declares one is `fsevents`, which is macOS-only and never
  installed in the Linux container. npm skips a blocked script without an
  error, so a future dependency that needs one installs cleanly and fails
  later, when it is used, possibly with an obscure missing-binary error.
  The setting also skips this package's own lifecycle scripts, such as
  `prepack` and `prepublishOnly`, and the `pre`/`post` hooks of any script
  run by name (`npm test` runs `test` but not `pretest`). So `package.json`
  carries no lifecycle or `pre`/`post` scripts: every gate and build step
  is its own `make` target, or a skipped hook would leave the gate green
  without it, or let a pack or publish ship an unbuilt package.
- **arm64 is unverified.** Apple-silicon machines run `linux/arm64`
  containers, and the spike ran only on x86_64. The image and all three
  tools publish arm64 builds, so it is expected to work; the first arm64
  contributor confirms it.
- **vite is pinned only by the lockfile.** Dependabot's version updates
  move direct dependencies. vite and rolldown move when a vitest bump
  requires it, or through a Dependabot security update.
- **TypeScript 7 is young.** It is the Go-native compiler, first stable
  release 2026-07-08. It drops the JavaScript compiler API, which nothing
  here uses: vitest and Biome parse TypeScript themselves. If a compiler
  bug bites, the fallback is pinning `typescript` 6.0.3, a one-line change.
- **Node 24 reaches end of life on 2028-04-30** (active LTS until
  2026-10-20, then maintenance). Moving to the next LTS line before then is
  a `FROM` change, plus edits to SPEC §7 and to any acceptance line that
  checks `v24.`. vitest 5.0.2 declares Node
  `^22.12.0 || ^24.0.0 || >=26.0.0`, so an odd-numbered line such as 25 is
  unsupported and the next move must be to an even (LTS) line.
- **Exact pins mean more Dependabot PRs.** Grouping keeps version updates
  to one PR a week per ecosystem. Security updates, which the vite bullet
  above relies on, arrive as separate PRs. Until Phase 2 adds the JS gate
  to CI, those npm and docker PRs are proved only by a local
  `make quality`.
- **Majors are manual.** Ignoring `semver-major` means nobody is prompted
  when a new Node line or tool major ships. The Node 24 end-of-life date
  above is the one that forces action. Dependabot applies `ignore` to
  security updates too: GitHub's "Controlling which dependencies are
  updated" page says ignore rules cover "version updates and security
  updates", and its note that `update-types` spares security updates sits
  under `allow`, not `ignore` (checked 2026-09-29, T-003; documented, not
  observed). So a security fix that exists only in a new major shows up as
  a Dependabot alert, not as a PR; a fix within the current major still
  arrives as a PR, provided Dependabot security updates are enabled in the
  repository settings (`dependabot.yml` does not control that).
- **Image and disk.** The image is 171 MB unpacked, and `node_modules`
  adds 130 MB in a named volume.

**Reversibility.** This is a two-way door. Nothing here reaches consumers,
and each choice can be swapped alone. The costliest swap is the test
runner, which means rewriting the imports and assertions in
`test/*.test.ts`. The RFC exists because AGENTS.md rule 3 requires one for
any dependency, not because the choice is hard to undo.

## Alternatives considered

- **`node:test` with Node's built-in type stripping.** This is the
  strongest alternative. Node 24.21 and 22.23 both run a `.ts` test file
  with no flag and no warning (checked in the spike), so it needs no test dependency
  and drops vitest and everything it pulls in, 35 of the 39 packages,
  from the tree.
  Passed on module resolution. `tsc` with `module: NodeNext` wants sources
  to import each other as `./distance.js`, and Node's type stripping does
  not map `.js` to `.ts`. The `node:test` path therefore needs `.ts`
  specifiers everywhere plus `allowImportingTsExtensions` and
  `rewriteRelativeImportExtensions` in `tsconfig.json`, and the spike did
  not test a multi-file `src/` that way. vitest resolves `.js` to `.ts`
  itself. Case naming is not a difference: a loop over a table names each
  `node:test` case as well as `test.each` does. Switching later means
  rewriting `test/*.test.ts` and editing SPEC §6.
- **ESLint + Prettier (with typescript-eslint).** The common pairing, but
  two tools, two configs, and many more packages than one Biome binary.
- **No linter or formatter**, relying on `tsc --strict`. Fewer packages,
  but formatting would drift between contributors, and SPEC §7 puts Biome
  in the pre-commit hook.
- **TypeScript 6.0.3**, the last JavaScript-based compiler. Mature, but
  it is the end of its line: new language features land in 7, so choosing
  6 now buys a forced migration later. Nothing here needs its JavaScript
  API. Kept as the fallback.
- **`node:22-alpine`**, which SPEC §7 named before this RFC. The spike
  passed on it too. Not chosen because Node 22 reaches end of life on
  2027-04-30, seven months after this RFC, which would force a Node
  migration within the year. The dev Node version never reaches
  consumers, who get ES2020 output, so choosing the longer-lived line costs
  nothing. The owner chose 24 at acceptance.
- **`node:24-slim` (Debian, glibc).** Removes the musl risk entirely, at
  the cost of a larger image. The spike found musl builds for every native
  tool, so SPEC §7's Alpine choice holds.
- **Tag-only image pin (`node:24-alpine`).** Simpler, but two builds of the
  same commit can get different images. A digest plus Dependabot gives the
  same freshness with reproducible builds.
- **pnpm or Bun instead of npm.** Either adds a tool on top of the npm that
  the image already ships, for speed this project does not need.
- **Do nothing.** Phase 1 cannot start: SPEC §12 blocks its first code on
  this RFC.

## Review and acceptance

- **rfc-reviewer, full round (2026-09-28):** 0 blockers, 4 should-fix,
  3 nits, all resolved in this draft. The `node:test` rejection now rests
  on module resolution, not on SPEC naming vitest. Node 24 is weighed
  against Node 22 (since chosen; see Owner acceptance). Dependabot ignores majors (Decision 4).
  `ignore-scripts` is described as silent, including for this package's
  lifecycle scripts. TypeScript 6 is rejected as end of line. The digest is
  confirmed multi-arch and arm64 is listed as unverified. Security-update
  PRs are noted as ungrouped.
- **rfc-reviewer, scoped round on those fixes (2026-09-28):** 1 fail-open
  path, resolved: `ignore-scripts` also skips `pre`/`post` hooks, so
  `package.json` carries no such scripts. 1 false claim, resolved:
  `node:test` is the one test-runner option with fewer packages. 1 check
  handed to T-003: whether ignoring majors also suppresses security-update
  PRs, now stated in "Majors are manual". The fixes are wording and a
  tightened rule, not a new mechanism, so there is no third round. Two
  nits parked in `docs/improvements.md`.
- **Owner acceptance (2026-09-28):** accepted, choosing `node:24-alpine`
  over `node:22-alpine`, the one choice the reviewed draft left open. The
  switch swaps a version already weighed in Alternatives, and the spike was
  re-run on the Node 24 digest. There is no mechanism change, so it gets no
  third review round (AGENTS.md rule 9). SPEC §7 and T-002's acceptance
  now say Node 24.
